# 교수 리서치 노트 개발 기록

## 1. 프로젝트 소개

2026년 여름, 제2회 호남권 SW중심대학사업 LLM 해커톤에 참여하여 **교수 리서치 노트** 프로젝트를 진행했습니다.

이 프로젝트는 대학 교수의 공식 프로필과 연구 정보를 보다 편리하게 찾아볼 수 있도록 돕는 서비스입니다.

교수의 이름과 소속 대학을 입력하면 관련 후보 정보를 검색하고, 사용자가 해당 교수를 확인한 후 연구 분야와 주요 논문, 경력 등의 정보를 정리할 수 있도록 기획했습니다.

프로젝트의 핵심 목표는 여러 웹사이트에 흩어져 있는 교수 정보를 한곳에서 확인하고, 정보의 출처도 함께 살펴볼 수 있도록 만드는 것이었습니다.

<!--more-->

## 2. 주요 기능

### 교수 정보 검색

사용자가 대학명과 교수명을 입력하면 관련 교수 정보를 검색합니다.

검색 결과를 바탕으로 사용자가 원하는 교수를 선택할 수 있도록 구성했습니다.

### 교수 정보 확인

검색 결과에서 이름, 대학, 학과 등의 정보를 확인하고 사용자가 올바른 교수인지 직접 선택하는 과정을 거칩니다.

이를 통해 이름이 같은 다른 교수의 정보가 잘못 연결되는 상황을 줄이고자 했습니다.

### 연구 정보 정리

확인된 교수의 연구 분야와 주요 논문, 경력 등의 정보를 수집하고 정리하는 기능입니다.

연구 정보에는 출처를 함께 제공하여 사용자가 원본 정보를 확인할 수 있도록 설계했습니다.

### 정보 검증과 보안

검색한 정보를 그대로 저장하는 것이 아니라 출처와 근거를 확인하는 과정을 중요하게 생각했습니다.

또한 URL과 응답을 검증하고, 공개적으로 접근할 수 있는 정보만 활용하도록 설계했습니다.

## 3. 사용 기술

프로젝트에서는 다음과 같은 기술을 활용했습니다.

- **Python:** 서버 측 개발 언어
- **FastAPI:** 백엔드 API 구성
- **Gemini:** 연구 정보 분석 및 구조화
- **OpenAlex:** 연구자와 논문 정보 활용
- **SQLite:** 데이터 저장
- **HTML, CSS, JavaScript:** 프론트엔드 개발
- **Vercel:** 서비스 배포

## 4. 나의 역할

이번 프로젝트에서 저는 **프론트엔드 개발**을 담당했습니다.

주요 작업은 다음과 같습니다.

- 사용자가 서비스를 이용하는 화면 구성
- 검색 및 정보 확인 과정의 사용자 인터페이스 구현
- 화면 요소와 사용자 인터랙션 구성
- 서비스의 전체 이용 흐름을 고려한 화면 설계
- 프론트엔드와 서비스 기능이 자연스럽게 연결되도록 작업

사용자가 검색부터 교수 확인, 연구 정보 확인까지 복잡하지 않게 이용할 수 있도록 화면의 흐름을 고민했습니다.

## 5. 프로젝트를 통해 배운 점

이번 해커톤을 통해 AI를 활용한 서비스에서는 단순히 정보를 많이 수집하는 것보다 **정확한 정보를 구분하고 신뢰할 수 있는 출처를 제공하는 과정**이 중요하다는 것을 배웠습니다.

특히 교수 이름이 같더라도 소속 대학이나 학과가 다를 수 있기 때문에, 사용자가 검색 결과를 확인하고 직접 선택하는 과정이 필요하다는 점을 알게 되었습니다.

또한 프론트엔드 개발을 진행하면서 화면을 만드는 것뿐만 아니라 사용자가 어떤 순서로 기능을 이용하는지 고려하는 것이 중요하다는 점도 경험했습니다.

팀 프로젝트를 통해 각 기능이 서로 연결되어야 하나의 서비스가 완성된다는 점을 배울 수 있었습니다.

## 6. 마무리

교수 리서치 노트 프로젝트는 LLM을 활용한 서비스의 가능성과 사용자 중심의 화면 설계를 함께 경험할 수 있었던 활동이었습니다.

앞으로도 다양한 프로젝트와 해커톤에 참여하면서 새로운 기술을 익히고, 실제 사용자의 문제를 해결할 수 있는 서비스를 개발하고 싶습니다.

**Tech Stack:** Python, FastAPI, Gemini, OpenAlex, SQLite, HTML, CSS, JavaScript, Vercel
