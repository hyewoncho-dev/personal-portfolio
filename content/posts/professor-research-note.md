# 교수 리서치 노트 개발 기록

## 1. 프로젝트 소개

2026년 여름, 제2회 호남권 SW중심대학사업 LLM 해커톤에 참여하여 **교수 리서치 노트** 프로젝트를 진행했습니다.

이 프로젝트는 대학 교수의 공식 프로필과 연구 정보를 보다 편리하게 찾아볼 수 있도록 돕는 웹 서비스입니다.

대학명과 교수명을 입력하면 관련 교수 후보를 검색하고, 사용자가 올바른 대상을 선택한 뒤 연구 분야와 주요 논문, 경력 등의 정보를 확인할 수 있도록 기획했습니다.

여러 웹사이트에 흩어져 있는 교수 정보를 한곳에서 확인하고, 정보의 출처까지 살펴볼 수 있도록 하는 것이 프로젝트의 주요 목적이었습니다.

- GitHub Repository: [Hackathon2026](https://github.com/hyewoncho-dev/Hackathon2026)
- Live Demo: [교수 리서치 노트](https://hackathone-pied.vercel.app/)

## 2. 주요 기능

### 교수 정보 검색

사용자가 대학명과 교수명을 입력하면 관련 교수 정보를 검색할 수 있습니다.

검색 결과를 통해 원하는 교수를 찾고 다음 단계로 이동할 수 있도록 구성했습니다.

### 교수 후보 확인

검색 결과에 이름이 같은 교수가 여러 명 있을 수 있다는 점을 고려했습니다.

사용자가 대학과 학과 등의 정보를 확인한 뒤 원하는 교수를 직접 선택하도록 하여 잘못된 인물의 정보가 연결되는 상황을 줄이고자 했습니다.

### 연구 정보 정리

선택한 교수의 연구 분야와 주요 논문, 경력 등의 정보를 확인할 수 있도록 구성했습니다.

정보를 제공할 때 출처를 함께 확인할 수 있도록 하는 것을 중요하게 생각했습니다.

### 논문 정보 연동

OpenAlex를 활용하여 연구자와 논문 정보를 연결하는 기능을 포함했습니다.

## 4. 나의 역할

이번 팀 프로젝트에서 **프론트엔드 개발**을 담당했습니다.

사용자가 서비스의 기능을 쉽게 이해하고 이용할 수 있도록 화면 구성과 사용자 인터랙션을 구현하는 데 참여했습니다.

주요 작업은 다음과 같습니다.

- 교수 정보를 검색하고 결과를 확인할 수 있는 화면 구성
- 사용자가 검색 정보를 입력할 수 있는 인터페이스 구성
- 검색 결과와 교수 후보를 확인하는 화면 흐름 구현
- 사용자의 선택에 따라 다음 단계로 이동할 수 있도록 화면 연결
- 서비스의 주요 기능을 사용자가 이해하기 쉽도록 화면 구조 정리

프론트엔드 개발에서는 화면을 단순히 보기 좋게 만드는 것뿐 아니라 사용자가 어떤 순서로 기능을 이용하는지 고려하는 것이 중요하다고 생각했습니다.

특히 검색부터 교수 선택, 연구 정보 확인까지 이어지는 과정이 자연스럽게 연결되도록 사용자 관점에서 화면 흐름을 고민했습니다.

## 5. 개발 과정에서 고민한 점

### 사용자가 정보를 쉽게 찾을 수 있는 화면 구성

교수 정보를 검색하는 서비스이기 때문에 사용자가 검색부터 결과 확인까지 어렵지 않게 진행할 수 있어야 했습니다.

이에 따라 검색 정보를 입력하고, 검색 결과를 확인한 뒤, 원하는 교수를 선택하는 순서로 서비스 흐름을 구성하는 것이 중요했습니다.

### 검색 결과의 정확성

교수 이름이 같더라도 소속 대학이나 학과가 다를 수 있습니다.

따라서 검색된 정보를 바로 확정하기보다 사용자가 후보 정보를 확인하고 직접 선택하는 과정이 필요하다는 점을 이해했습니다.

### 정보의 신뢰성

AI가 정리한 정보라고 해서 모든 내용이 정확한 것은 아닙니다.

공식 프로필과 연구 정보의 출처를 함께 제공하고, 사용자가 원본 정보를 확인할 수 있도록 하는 것이 중요하다고 생각했습니다.

## 6. 프로젝트 결과

대학명과 교수명을 바탕으로 교수 정보를 검색하고, 후보를 확인한 뒤 연구 및 논문 정보를 살펴볼 수 있는 웹 서비스 구현에 참여했습니다.

이번 프로젝트를 통해 팀원들과 역할을 나누어 하나의 서비스를 개발하는 경험을 얻었으며, 프론트엔드 화면이 백엔드 기능 및 데이터와 연결되는 과정을 이해할 수 있었습니다.

- GitHub: [프로젝트 소스 코드](https://github.com/hyewoncho-dev/Hackathon2026)
- Demo: [배포된 웹 서비스](https://hackathone-pied.vercel.app/)

## 7. 프로젝트를 통해 배운 점

이번 해커톤에서 가장 크게 배운 점은 **사용자의 관점에서 서비스의 흐름을 설계하는 것**이 중요하다는 사실입니다.

기능 자체가 잘 작동하더라도 사용자가 어떤 정보를 입력해야 하는지, 검색 결과를 어떻게 확인해야 하는지 이해하기 어렵다면 좋은 서비스가 되기 어렵다는 점을 느꼈습니다.

또한 프론트엔드 개발을 담당하면서 화면의 구성 요소와 서비스 기능이 서로 연결되어야 하나의 완성된 서비스가 된다는 것을 경험했습니다.

LLM을 활용한 프로젝트를 진행하며 AI가 제공하는 정보를 무조건 신뢰하기보다 출처와 근거를 확인하는 과정도 중요하다는 점을 배웠습니다.

## 8. 아쉬웠던 점과 향후 개선 방향

해커톤 기간 안에 프로젝트를 진행하면서 다양한 기능을 충분히 검증하고 사용자 경험을 세밀하게 개선하는 데에는 한계가 있었습니다.

앞으로 다음과 같은 부분을 개선해 보고 싶습니다.

- 다양한 검색어에 대한 검색 결과의 정확성 개선
- 검색 결과와 교수 후보를 더 쉽게 비교할 수 있는 화면 구성
- 연구 및 논문 정보의 출처를 명확하게 확인할 수 있는 인터페이스 개선
- 로딩 및 오류 상황에서 사용자가 현재 상태를 쉽게 이해할 수 있도록 안내 강화
- 실제 사용자의 의견을 반영한 화면과 기능 개선

이번 프로젝트는 웹 개발과 AI 기술이 결합된 서비스를 경험하고, 팀 프로젝트에서 프론트엔드 개발자의 역할을 이해할 수 있었던 좋은 기회였습니다.

앞으로도 다양한 프로젝트에 참여하면서 사용자에게 실질적인 도움이 되는 서비스를 만드는 개발자로 성장하고 싶습니다.
